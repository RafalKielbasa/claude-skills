# Backing up Claude configuration to the `claude-skills` repository

Date: 2026-09-03
Status: approved design, implementation pending

## Problem

Work with Claude Code is spread across eight `.claude` directories on two drives. They
hold 17 skills, one agent, global and per-project configuration, and 80 memory files.
None of it is backed up anywhere but the disk itself. A drive failure or a new computer
wipes all of it.

Goal: one private repository that can restore the whole setup onto a clean machine.

## Architecture

### An allowlist, not a denylist

`.gitignore` opens with `*` and `!*/`: every file at every level is ignored by default,
while git still descends into directories. Explicit exceptions for the paths in
"What goes in" follow.

Reason: Claude Code adds new state directories on every update. A denylist would admit
each new one on the day it appears, and only a diff review would catch it. An allowlist
makes them invisible by default.

Hard blocks sit at the end of the file and override every exception above:
`.credentials.json`, `*.key`, `*.pem`, `.env`, `.env.*`, `*.jsonl`. They protect against
an over-broad exception added later.

### Rejected alternatives

**A repository outside `.claude`, mirroring everything.** Symmetric, but it contradicts
the requirement that the repository live in this directory, and it loses in-place
versioning of the global configuration — a change to `settings.json` would surface only
after a sync rather than immediately as a diff.

**Git submodules per location.** No duplication and two-way editing, but it means seven
additional repositories, submodules over paths containing spaces (`Baza wiedzy`,
`saas app`, `Multi agent system`) on Windows, and a restore that requires recursive
cloning into specific locations. Disproportionate to the problem.

## Components

### `hooks/backup-claude.ps1`

The only path for automated syncs, and the sole producer of commits once the repository
is in service.

The invariant is narrower and more precise than "never run `git commit` here": **no
commit is made in this repository without the secret scanner having passed over its
staged set.** During implementation, hand-made commits of source files are normal — they
satisfy the invariant by running `Test-SecretContent` over the staged files first, which
is the same check the script performs. Stating the rule as "only through the script"
would be a rule the implementation itself breaks eight times, and a rule broken in its
own plan is not a rule.

Parameters: `-Rescan`, `-NoPush`, `-Verbose`.

Sequence:

1. **Lock.** `backups/.sync.lock`. Present and younger than 10 minutes → exit 0. Protects
   the git index from two sessions ending at the same moment.
2. **Registry.** Reads `backups/claude-dirs/registry.json` (slug to absolute path). With
   `-Rescan` it walks `D:\` and `C:\Users\rafal` to a depth of 6, pruning `node_modules`,
   `.git`, `AppData`, `.vscode`. New locations are appended; paths that no longer exist
   are flagged `"missing": true` and **their mirrors are kept**. A deleted project must
   not delete its own backup — that is the one thing a backup exists to prevent.
3. **Mirroring.** Copies the allowlisted names from each source into
   `backups/claude-dirs/<slug>/`. Within those paths it behaves as a mirror: a file
   deleted at the source disappears from the copy, so a removed skill does not come back
   to life on restore.
4. **Secret gate.** Scans the content of every staged file for key patterns. A hit aborts
   before the commit, writes to `backups/sync.log`, and exits 1.

   Size is not an exemption: a large text file is read in 1 MB chunks with an overlap
   wide enough that no pattern can straddle a chunk boundary. Only files detected as
   binary — a NUL byte within the first 8 KB — are skipped, because a regex over binary
   content yields noise, not findings.

   Every pattern requires a **key body of minimum length**, never a bare prefix:
   `sk-ant-[A-Za-z0-9_-]{24,}`, `ghp_[A-Za-z0-9]{36}`, `github_pat_[A-Za-z0-9_]{40,}`,
   `AIza[0-9A-Za-z_-]{35}`, `-----BEGIN [A-Z ]*PRIVATE KEY-----`,
   `"(accessToken|refreshToken)"\s*:\s*"[^"]{20,}"`.

   The reason is concrete: this spec, the implementation plan and the tests all name key
   prefixes as text. A pattern matching a bare prefix would block commits of the
   project's own documentation — the gate would shut down the project it protects.
   Requiring a body separates "a description of a pattern" from "a key".
5. **Conditional commit.** `git add -A`, then `git diff --cached --quiet`. No differences
   → no commit. No junk commits after sessions that changed nothing. Every `git`
   invocation whose outcome matters has its `$LASTEXITCODE` checked: Windows PowerShell
   5.1 does not turn a native program's non-zero exit into a terminating error, so
   `$ErrorActionPreference = 'Stop'` would let a failed `git add` pass for success.
6. **Push.** `git push origin main`. Failure is logged and exits 0 — the local commit
   exists and the next run will push it. The retry is real rather than aspirational: the
   run compares `main` against `origin/main` and pushes any unpushed commits **also on
   the no-changes path**, which is exactly the path a retry after a failed push takes.

Commit message from the hook: `backup: sync .claude config (N files) YYYY-MM-DD HH:mm`.
English and ASCII only — Windows PowerShell 5.1 passes arguments to `git.exe` in the ANSI
codepage, so non-ASCII characters in `-m` land in history mangled. Commits made
deliberately during a session carry the `Co-Authored-By` trailer and a session link.

Limitation: a newly created `.claude` directory does not enter the registry without
`-Rescan`. Rescanning on every run was rejected — seconds of delay after every session in
exchange for information that changes about once a month.

### `hooks/restore-claude.ps1`

Fans the mirrors in `backups/claude-dirs/` back out to the paths in `registry.json`.

- **Dry by default.** Without a flag it prints the planned operations. Overwriting files
  requires `-Apply`. A restore overwrites someone's work, so it must not happen by
  accident.
- **Path remapping.** `-Map "D:\Praca=E:\Praca"`. This also covers the
  `projects/<slug>/memory/` directories: their names derive from the project path, so
  without remapping Claude would not find its memory after a drive letter change.
  Prefix matching respects path segment boundaries: the old prefix must be followed by a
  separator or end the path, so `D:\Praca` does not also capture `D:\Pracownia`.
- An entry flagged `"missing": true` is restored if its target path exists after
  remapping; otherwise it is reported and skipped.
- **Overwrites, never deletes.** Files present in the target `.claude` but absent from
  the mirror are left alone. On a clean machine the target is empty, so this changes
  nothing; when restoring over a populated directory it means a stale file can survive.
  Deleting someone's working files during a restore is worse than leaving a stale one,
  so the destructive variant is not implemented.

### The `SessionEnd` hook

Registered in `settings.json` through the `update-config` skill, with `timeout: 120`. The
hook is global, so it fires after a session in any directory — including `Baza wiedzy` and
`Notatki`, where 13 of the 17 skills live.

Note: `D:\Praca\Devstock\Baza wiedzy\.claude\settings.json` denies `Bash(git commit:*)`
and `Bash(git push:*)`. That denial applies to Claude's tool permission layer, not to hook
processes — the script will run there. This is intended.

If verification shows that `SessionEnd` is not supported by the installed version of
Claude Code, the hook attaches to `Stop` instead.

### `README.md`

Restore procedure for a clean machine:

1. Install Claude Code and sign in (`.credentials.json` is deliberately out of the
   repository).
2. Attach the repository to the existing `~/.claude`:
   ```powershell
   git clone https://github.com/RafalKielbasa/claude-skills.git "$env:TEMP\claude-skills"
   Move-Item "$env:TEMP\claude-skills\.git" "$env:USERPROFILE\.claude\.git"
   cd "$env:USERPROFILE\.claude"; git checkout -- .
   ```
   Moving just `.git` makes the restored directory a repository immediately, able to keep
   committing without further setup. Cloning straight into `~/.claude` fails because
   Claude Code creates files there on first launch.
3. `hooks\restore-claude.ps1 -Apply` (with `-Map` if paths changed).
4. Reinstall plugins from the manifest:
   ```
   /plugin marketplace add anthropics/claude-plugins-official
   /plugin marketplace add kepano/obsidian-skills
   /plugin install superpowers@claude-plugins-official
   /plugin install figma@claude-plugins-official
   /plugin install obsidian@obsidian-skills
   ```
   Installation yields the latest versions, not the ones from before the failure. The
   manifest records the previous state (`superpowers 6.3.0 @ b557648`,
   `figma 2.2.107 @ a742f0a`, `obsidian 1.0.1 @ a1dc48e`) in case a new version regresses.
5. Verification: `/skills` lists the global skills, `/hooks` shows `SessionEnd`,
   `projects/*/memory/` holds 80 files.

The README also carries a "what is deliberately absent" table, so that nobody hunts
mid-outage for something that was never backed up.

## Testing

| What | How |
|---|---|
| The allowlist admits no secrets | after `git add -A`, `git diff --cached --name-only` contains no `.credentials.json`, `*.jsonl`, `*.key`, `plugins/cache/` |
| File count is sane | `git ls-files \| wc -l` matches the expected total from "What goes in" |
| The secret gate works | a fixture containing an Anthropic-shaped key under `skills/` → exit code 1, no commit, an entry in `sync.log` |
| The mirror propagates deletions | deleting a file in a source `skills/` → after a sync it is gone from `backups/claude-dirs/<slug>/` |
| No changes means no commit | two consecutive runs → the second exits 0 and `git log` gains no entry |
| The lock works | creating `.sync.lock` by hand → the run exits 0 without a commit |
| A vanished source keeps its mirror | temporarily renaming a source directory → `-Rescan` flags the entry `missing` and the files under `backups/` remain |
| The restore is faithful | `restore-claude.ps1 -Apply -Map` into a temporary directory, then compare the mirrored paths against the original; files outside the mirror set are not part of the comparison, because restore does not delete |
| Remapping respects segment boundaries | `-Map "D:\Praca=E:\Praca"` leaves an entry under `D:\Pracownia` untouched |
| Push retries after a failure | with the remote unreachable a commit is made and the push fails; with the remote back and nothing else changed, the next run pushes it |
| Git failures are noticed | a `git add` that exits non-zero aborts the run instead of logging success |

## Open risks

- The push from the hook happens without the user in the loop. The guards are the
  allowlist and the secret scanner; both are code, not judgment.
- The registry needs a manual `-Rescan` after a new `.claude` directory appears.
- Plugin restore is not version-faithful.
- The copies in `backups/claude-dirs/` are one-way. Editing a file in a copy does not
  change the source and will be overwritten by the next sync.
